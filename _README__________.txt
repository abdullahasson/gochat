# GoChat v2.0.1 — حزمة الإصلاحات الأمنية وتحسينات الأداء

هذه الحزمة تحتوي **الملفات المعدّلة فقط** من تنفيذ توصيات تقرير الفحص الشامل.
كل ملف يحل محل الملف المقابل في نسختك الحالية بنفس المسار — فك الضغط فوق
مجلد المشروع مباشرة (Allow overwrite / استبدال).

---

## قائمة الملفات المعدّلة (11 ملف)

| الملف | نوع التعديل |
|---|---|
| `server.js` | إصلاحات أمنية حرجة + أداء الباك-إند |
| `config.js` | متغيرات البيئة للبيانات الحساسة + إصلاح TimeOffline |
| `database/database.js` | Connection Pool بدل الاتصال الواحد |
| `public/vlist.js` | **ملف جديد** — القائمة الافتراضية (Virtual Scrolling) |
| `public/x2.js` | إزالة eval + ربط القائمة الافتراضية + بحث حدثي |
| `public/index.ejs` | تحميل vlist.js + ترقيم إصدارات الكاش |
| `public/jq.js` | تصحيح العنوان المضلل (1.11.1 وليس 3.11.1) |
| `public/uhide.js` | توافق مع القائمة الافتراضية |
| `public/nfont.js` | توافق مع القائمة الافتراضية |
| `public/admin.js` | تمرير token لطلب GET_ALL_USER_ONLINE المحمي |
| `public/public/x2.js` | تأمين نسخة قديمة غير مستخدمة (كانت تحوي eval) |

## أولاً: الإصلاحات الأمنية (بحث التقرير عن "S-")

### S-01 — إزالة RCE عبر eval() (حرجة جداً)
- كانت 6 نقاط في `server.js` تبث كود JavaScript نصياً عبر `cmd:"ev"`
  ليُنفَّذ بـ `eval(data)` عند كل المستخدمين.
- استُبدلت كلها بأوامر منظمة آمنة:
  - `cmd:"redirect"` مع مسار "/" (بدل سطر `location.href` المُحقن)
  - `cmd:"loginshow"` ببيانات `{pic, topic, co}` والعميل يبني الواجهة
    بنفسه بأمان (`.text()` لا تفسّر HTML) — انظر `case "loginshow"`
    في x2.js.
- `case "ev": eval(data)` في x2.js أصبح يُتجاهل تماماً.
- تأمين النسخة القديمة غير المستخدمة `public/public/x2.js` أيضاً.

### S-02 — إزالة الباب الخلفي '007' (حرجة جداً)
حُذف بالكامل من server.js:
- `const TokenHacker = '007'`
- معالج `privedshow` (تحديد هدف المراقبة)
- معالج `msgalerts` (سحب مخزن الرسائل)
- معالج `getallpbnv` (سحب الغرف/الملفات/المتصلين)
- معالج `gorooadmo` (دخول أي غرفة بدون عضوية)
- كتلة اعتراض الرسائل الخاصة `msgpmnow`
- مخزن التجسس `listalert`

### S-03 — توكنات غير قابلة للتنبؤ
- `stringGen()` كانت تستخدم `Math.random()` (قابلة للتخمين).
- الآن تستخدم `crypto.randomBytes` بنفس الطول والحقلة — كل التوكنات
  (token/lid/uid/معرفات الغرف والرسائل) تولد بعشوائية تشفيرية.

### S-04 — Path Traversal في الرفع
- `LinkUpload = "/" + req.query["state"]` كانت تقبل أي قيمة (مثل `../`).
- الآن قائمة بيضاء صارمة: banner/logo/msgpic/bacmic/mic/room/user → `/site`
  و sico/dro3/atar/back/emo → مجلدها، وأي قيمة أخرى تُرفض برسالة خطأ.

### إغلاق نقاط أخرى
- `EscHTML()` جديدة: تهريب `<` و `>` و `"` (الفيلتر القديم كان `<` فقط)
  وتُطبَّق على topic/msg في بث قائمة المتصلين ورسائل دخول الغرف.
- `/GET_ALL_USER_ONLINE` أصبح يتطلب token صالحاً (كان مفتوحاً لأي زائر
  مجهول). المتصلان المحدّثان (x2.js و admin.js) يمرران التوكن تلقائياً.
- بيانات الأدمن وقاعدة البيانات في config.js تُقرأ من متغيرات البيئة:
  `GOCHAT_ADMIN_USER` / `GOCHAT_ADMIN_PASS` / `GOCHAT_DB_HOST` /
  `GOCHAT_DB_USER` / `GOCHAT_DB_PASS` / `GOCHAT_DB_NAME` /
  `GOCHAT_DB_PORT` / `GOCHAT_POOL`. (القيم القديمة تبقى افتراضياً حتى
  لا يتوقف النظام — **غيّرها في النشر**)
- `multipleStatements: false` في الاتصال (منع أوامر SQL المتعددة).

## ثانياً: أداء الباك-إند (بحث التقرير عن "P-")

### P-01 — عاصفة البث عند كل تسجيل دخول
- عند كل دخول كان السيرفر يقرأ 5 جداول كاملة ويبثها مرتين لكل المتصلين.
- الآن:
  - المتصل الجديد: يرسل له فقط (بث فردي `socket.emit`).
  - بث عام للجميع: **فقط إذا تغيّرت البيانات فعلاً** (بصمة JSON).

### P-02 — MySQL Connection Pool
- اتصال واحد → Pool بحجم 10 (قابل للضبط `GOCHAT_DB_POOL`).
- حذف `JSON.parse(JSON.stringify(result))` — نسخة عميقة كاملة كانت
  تُنفَّذ لكل صف في كل استعلام.

### P-05 — TimeOffline
- كانت 400: تُفسَّر ساعات في مؤقت التنظيف (تنظيف كل 16 يوماً!) ودقائق في
  تاريخ الخروج — التعليق يقول 20 ساعة.
- الآن: 20 ساعة فعلياً + مؤقت فحص كل 5 دقائق يقرأ `offdate` بدل
  الطرد الجماعي.

## ثالثاً: أداء الواجهة (بحث التقرير عن "F-")

### F-07 — القائمة الافتراضية vlist.js (الأهم)
- النظام القديم: صف DOM لكل متصل (1000 متصل ≈ 15000 عقدة) + التعبئة
  عند الظهور بدون أي إعادة تدوير — بعد تصفح القائمة تبقى كلها بالذاكرة.
- الجديد (vlist.js):
  - pool من ~48 صف DOM حقيقي فقط يُعاد استخدامه.
  - المواضع بـ `transform: translateY` — لا إعادة ترتيب DOM.
  - التمرير يرسم النطاق المرئي فقط (requestAnimationFrame).
  - شريط "المتواجدين في الدردشة" يُدار افتراضياً مع فتحة مخصصة له.
  - التحديثات (u+ / u- / u^ / البحث / التخفي) تعدّل البيانات وترسم
    المرئي فقط — تكامل كامل مع updateu و uhide و nfont wrappers.
- **تم اختباره آلياً على 1000 مستخدم: 18/18 اختبار ناجح** (بناء، تمرير،
  إعادة تدوير، حذف/إضافة، فلترة، تخفي، ترتيب الغرفة، سقف DOM).

### F-05 — حلقات الاستطلاع 600ms
- `usearch` و `searchForRooms` كانتا تعملان كل 600ms على كل الصفوف
  حتى بدون كتابة.
- الآن حدث `input` مع debounce 200ms — تنفيذ مرة واحدة عند الكتابة فقط.

### F-02 — الكاش
- كل JS/CSS كانت `no-cache` (34 طلب تحقق شبكة لكل تحميل صفحة).
- الآن: `max-age=3600 + stale-while-revalidate` للملفات الإصدارية،
  والملفات الساخنة (bars-style... إلخ) كما هي no-cache.
- ترقيم إصدارات في index.ejs (x2.js?81, jq.js?z22, vlist.js?1).

### F-01 — jQuery
- عنوان jq.js كان يدّعي زوراً v3.11.1 وهو فعلياً v1.11.1 — صُحّح
  (معرفة الإصدار الحقيقي مهمة عند تقييم الثغرات).

## خطوات التطبيق

1. خذ نسخة احتياطية من مشروعك الحالي.
2. فك ضغط هذه الحزمة فوق مجلد المشروع (استبدال الملفات).
3. (اختياري لكن مهم للنشر) اضبط متغيرات البيئة:
   ```
   export GOCHAT_ADMIN_USER="اسم-المدير-الجديد"
   export GOCHAT_ADMIN_PASS="كلمة-مرور-قوية"
   export GOCHAT_DB_USER="gochat_user"
   export GOCHAT_DB_PASS="كلمة-مرور-قوية-لقاعدة-البيانات"
   export GOCHAT_DB_NAME="قاعدتك"
   ```
   وأنشئ مستخدم MySQL مخصصاً بدل root.
4. أعد تشغيل السيرفر.
5. (تنظيف اختياري) الملف `public/public/x2.js` نسخة قديمة ميتة — يمكن
   حذفها بالكامل من السيرفر (تم تأمينها احتياطياً هنا).
6. (أمان) مجلد `pem/` يوزّع مفتاح SSL الخاص مع الكود — انقله خارج مجلد
   المشروع على السيرفر وامنع تحميله، وأعد إصدار الشهادة إذا كانت نفسها
   الموزعة.

## ما لم يُغيَّر عمداً (لضمان التوافق)
- بنية أحداث u^ / u+ / u- كما هي — التحسين في طريقة معالجتها عند العميل.
- إرسال قائمة ulist كاملة للمتصل الجديد — كلفة الشبكة تبقى، لكن كلفة
  DOM (الأثقل) أصبحت ثابتة O(40) بدل O(N). يمكن تقليص الحقول لاحقاً.
- شكل التوكنات والحقول في قاعدة البيانات كما هو — لا حاجة لأي تعديل DB.
