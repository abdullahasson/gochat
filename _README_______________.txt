# CodyChat — حزمة إصلاحات الأداء (تنفيذ تقرير التدقيق الشامل)

هذه الحزمة تنفّذ **كل توصيات تقرير تدقيق الأداء** (CodyChat_Performance_Audit.html)
بعد موافقة المالك: «طبق كل الاصلاحات بأفضل الطرق الممكنه والمتاحه».

كل تعديل داخل الكود معلَّم بتعليق يبدأ بـ **[FIX-Cxx]** (رقم المشكلة في التقرير)
مع شرح ما كان وما صار — يمكن تتبّع كل إصلاح بالبحث عن `FIX-C` في الملفات.

**القاعدة الحاكمة في كل التعديلات:** لا حذف أي ميزة، لا تغيير في أسماء أحداث
Socket.IO أو بروتوكولاتها، لا تغيير في التصميم/الواجهة، ولا تغيير في ترتيب
الرسائل أو سلوك الإرسال — فقط طريقة التنفيذ (كيف) وليس السلوك (ماذا).

---

## قائمة الملفات المعدّلة (8 ملفات + ملف جديد)

| الملف | نوع التعديل |
|---|---|
| `public/x2.js` | 22 إصلاحًا: P0 الكيبورد/السكرول/الإرسال + مسارات الخاص/الحائط/القوائم |
| `public/index.ejs` | إزالة السحب القسري من tbox + حذف DataTables + استخراج 77KB CSS + ترقيم الكاش |
| `public/chat-core.css` | **ملف جديد** — CSS المستخرج من index.ejs (قابل للتخزين المؤقت) |
| `public/vlist.js` | قائمة المتصلين: فرز واحد لكل دفعة + تعبئة مختزلة أثناء التمرير + تفويض |
| `public/nfont.js` | تضييق مراقب الطفريات من body كاملاً إلى حاويات المحتوى الست |
| `public/user-status.js` | heal يعمل فقط عند فتح تبويب المتصلين |
| `public/settings-style.js` | مزامنة موجّهة بالأحداث بدل استطلاع 300ms الأبدي |
| `public/silent-reconnect.js` | حذف مستمع presort الدائم + مراقب تكيفي (2s/5s) |
| `server.js` | تقليص بث تغيير الحالة إلى {id, stat, rep} بدل كائن كامل |

التركيب: انسخ الملفات فوق مجلد المشروع بنفس المسارات (استبدال)، ثم **أعد
تشغيل السيرفر** (server.js تغيّر). لا حاجة لأي خطوة أخرى — لا قاعدة بيانات
ولا اعتمادات جديدة.

## أولاً: إصلاحات P0 الحرجة (تخص شكوى «ثقل الكيبورد وقفز السكرول»)

### C-01 — سحب السكرول القسري من لمسة مربع الكتابة (index.ejs)
- كان: أي لمسة على #tbox تسحب سكرول الرسائل للأسفل بعد 250ms —
  قارئ الرسائل القديمة يُقذف للأسفل مع كل لمسة كتابة.
- صار: حُذف الجزء القسري وبقي إغلاق البوب أوفر فقط. التمرير عند وصول
  رسالة جديدة يُدار الآن بشرط «قريب من الأسفل» (C-03).

### C-02 — fixSize: Layout Thrashing + تنفيذ مزدوج + سحب سكرول (x2.js)
- كان: كل resize (ويشمل فتح/غلق الكيبورد) يشغّل fixSize مرتين متتاليتين
  (فوري + setTimeout 10ms) مع كتابات/قراءات CSS متداخلة لكل عنصر
  (.filw/.filh: قراءة-كتابة-قراءة-كتابة...)، وينتهي بسحب سكرول #d2 قسرًا.
- صار:
  - كل استدعاءات الإطار الواحد تُدمج في تمريرة rAF واحدة (`__fixRaf`).
  - docss: كل القراءات أولًا ثم كل الكتابات في نهاية واحدة (jobs[]).
  - التمريرة الثانية صارت إطارًا تاليًا (نفس دور setTimeout 10ms القديم
    لإعادة القراءة بعد استقرار الكتابة).
  - سحب سكرول #d2 مشروط بقرب المستخدم من آخر الرسائل (< 120px).
  - إضافة مستمع visualViewport (بديل iOS الصحيح لحدث resize الذي لا
    يطلقه الكيبورد هناك) مع debounce 120ms أثناء حركة الكيبورد.

### C-03 — تمرير قسري لكل رسالة واردة (x2.js — AddMsg)
- كان: `w.scrollTop(w[0].scrollHeight)` مع كل رسالة، بلا أي فحص لموقع
  المستخدم — يقطع قراءة التاريخ مع كل رسالة جديدة.
- صار: قراءة الموقع **قبل** تعديل DOM: النزول فقط إذا كان المستخدم قريبًا
  من الأسفل (< 80px) أو كانت الرسالة من المستخدم نفسه (uid == M_ID)،
  والكتابة نفسها داخل rAF واحدة (تحافظ على «اللحظية» بلا تخطيط متزامن).

### C-04 — مسار الإرسال يمرّ بتمريرة تخطيط كاملة (x2.js)
- كان: كل Enter يمرّ بـ norpl() ← fixSize() (docss على كل .filw بالصفحة)
  حتى بدون رد معروض — هذا هو «ثقل زر الإرسال».
- صار: norpl ينفّذ fixSize فقط عند وجود رد فعلي (replaymsg يعيد الحجم
  عند فتحه فيبقى التناظر). ثانويًا: الالتقاط صار keydown (مع preventDefault
  قبل إدراج السطر) مع تجاهل isComposing للكتابة العربية بالتصحيح التلقائي،
  وkeyup القديم باقٍ كشبكة أمان (Tsend يتجاهل النص الفارغ فلا إرسال مزدوج).

### C-05 — رقعة تعطيل localStorage بالكامل (x2.js)
- كان: `Storage.prototype.getItem = () => null` عند كل اتصال — تكسر
  getv() كلها: حفظ الاسم/كلمة المرور/الإحالة/قائمة التجاهل، وميزة
  «حالتي الآن» (user-status.js يقرأ myStatus مباشرة بعد الاتصال).
- صار: تعطيل قراءة بصمة الجهاز فقط (fp1/cc) — نفس غرض الحماية من العبث
  بالبصمة دون كسر أي ميزة. والرقعة idempotent فلا تتراكب عبر إعادة الاتصال.

## ثانيًا: إصلاحات P1 عالية الأثر

### C-06 — إعادة بناء قائمة المتصلين لكل عضو يدخل (vlist.js + x2.js)
- كان: كل u+ يستدعي VLIST.add **+** VLIST.touch = rebuild وفرز O(N log N)
  مرتين لكل عضو — دفعة دخول (بعد ريستارت مثلًا) = عشرات الفرزات.
- صار: VLIST.add(id) يعلّم orderDirty + يجدول رسمًا واحدًا — دفعة متتالية
  تنتهي بفرز واحد داخل إطار واحد (render ينفّذ rebuild عند وجود العلم).

### C-07 — إعادة تدوير الصف أثناء التمرير السريع (vlist.js)
- كان: كل صف يعاد تدويره أثناء السكرول يمرّ عبر updateu الكاملة (jQuery
  ثقيل: ~15 find/css لكل صف).
- صار: أثناء الحركة تعبئة مختزلة بـ DOM مباشر (صورة+اسم+رسالة+حالة+رقم)،
  وبعد توقف التمرير 160ms تُستكمل التعبئة الكاملة عبر updateu.

### C-08 — مراقب طفريات على body كامل (nfont.js)
- كان: MutationObserver على document.body بـ subtree — أي إدخال DOM في
  التطبيق كله (رسائل، صفوف، نوافذ، شارات) يدفع عناصره للطابور ويُمسح
  بـ jQuery بحثًا عن data-uh.
- صار: المراقبة على حاويات المحتوى الموسوم فقط: #room و.dad و#wall
  و#wetchprofilenotifi و#cooment و#upro (نفس نمط yt-wall/users-style
  الموجود في المشروع أصلًا). المسارات الأساسية مغطاة مباشرة عبر أغلفة
  uhideTag/updateu/PC_ONPROFILE كما كانت.

### C-09 — زر الرد مزدوج الربط (x2.js — AddMsg)
- كان: onclick مضمّن + jQuery .click معًا — replaymsg يُنفَّذ مرتين لكل
  ضغطة (يفتح شريط الرد مرتين).
- صار: ربط jQuery واحد فقط ببيانات من الكائن مباشرة (نفس بيانات آخر
  استدعاء في السلوك القديم — لا تغيير في مضمون الرد).

### C-10 — مؤقتات أبدية تعمل والصفحة خاملة (x2.js + settings-style + user-status + silent-reconnect)
- كان: ستة مؤقتات دائمة، أثقلها: 300ms يفحص `:visible` (يجبر تخطيطًا
  متزامنًا) في settings-style، وCHECK_UP كل 2s بفحوص `:visible` jQuery،
  وheal كل 1s يعيد تزيين كل الصفوف واللوحة مغلقة، ومراقب إعادة الاتصال
  كل 2s للأبد.
- صار:
  - settings-style: المزامنة تُطلق بحدث التبويب + مراقب سمات #dpnl
    (يلتقط .show()/.hide())، وتتوقف ذاتيًا عند الإغلاق — صفر عمل مغلقًا.
  - CHECK_UP: بوابات رخيصة (inline display + classList) بدل `:visible`.
  - heal: يعمل فقط عند ظهور تبويب المتصلين + مرور فوري عند فتحه.
  - مراقب إعادة الاتصال تكيفي: 2s أثناء المشاكل، 5s عند الاستقرار.
  - (مؤقتا music-player كانا محميين أصلًا بـ document.hidden — بقا كما هو).

### C-11 — مسار الرسائل الخاصة الكامل لكل رسالة (x2.js)
- كان: كل رسالة خاصة تبحث $("#c"+pm) خمس مرات، تنقل الصف لأعلى قائمة
  المحادثات دائمًا، وتمر بكامل openw.
- صار: مرجع واحد يعاد استخدامه، والنقل فقط إذا لم يكن الصف على القمة
  أصلًا، وopenw يخرج مباشرة بعد تحديث «غير المقروء» والعدّاد للرسائل
  الواردة على نافذة موجودة، وعند الفتح تُخفى النوافذ مباشرة بدل نقر
  اصطناعي على كل .phide (نفس الأثر بالضبط).

### C-12 — تراكم مستمع سكرول الحائط (x2.js)
- كان: `$(".d2bc").on("scroll",...)` داخل case "login" — يتراكم مستمع
  جديد مع كل إعادة اتصال صامتة.
- صار: علم `__bcScrollBound` يضمن الربط مرة واحدة (العنصر ثابت أصلًا).

### C-13 — بث كائن المستخدم كاملًا مع كل تغيير حالة (server.js)
- كان: أي عضو يعود للنشاط بعد خمول = io.emit لكائنه كاملاً (اسم، صورة،
  ألوان، غرفة، قوى...) لكل المتصلين.
- صار: البث {id, stat, rep} فقط — العميل يدمجها محليًا في U_CASH عبر
  Object.assign (معالج u^ يدعم الحقول الجزئية أصلًا — توافق تنازلي كامل).

### C-14 — فتح ملف أي عضو يعيد بناء قائمة الغرف (x2.js — upro)
- كان: socket.emit('vistor') حتى لفتح ملفي أنا + بناء options لكل غرفة
  بقراءة DOM لكل واحدة.
- صار: vistor يُرسل فقط لغيري، وقائمة الغرف من كاش يُبطَل فقط عند
  r+/r-/r^/rlist. (الفرز القديم كان يعمل على تحديد فارغ «#rooms .roomz»
  أي لم يكن ينفذ أصلًا — سُجل ذلك وحُذف).

### C-15 — كتابة تمرير مزدوجة + قراءة إجبارية لكل منشور حائط (x2.js)
- كان: لكل منشور: قراءة scrollTop إجبارية + كتابة تُلغى فورًا + قراءة
  innerHeight إجبارية — تحميل 60 منشورًا = ~120 إجبار تخطيط متزامن.
- صار: كتابة واحدة مؤجلة عبر rAF (تُدمج للمنشورات المتتالية) — نفس
  السلوك: البقاء في أعلى الحائط.

### C-16 — شاشة الدخول: إعادة بناء كل 5 ثوانٍ (x2.js)
- كان: تفريغ وإعادة بناء قائمة المتصلين كاملة كل 5s لكل زائر حتى بدون
  تغيير، للأبد.
- صار: بصمة سريعة للبيانات — تخطّي كامل إذا لم تتغير، بناء في
  DocumentFragment واحد عند التغيير، loading=lazy للصور، واستطلاع تدريجي
  (5s ثم 10s بعد دقيقة انتظار)، ويتوقف كالمعتاد عند الدخول.

## رابعًا: كيف تتأكد أن كل شيء يعمل (فحص سريع بعد النشر)

1. **الكيبورد (P0):** افتح الشات بالموبايل → المس مربع الكتابة — لا يجب
   أن يقفز سكرول الرسائل. افتح/أغلق الكيبورد مرارًا — بلا تهنيج/وميض.
2. **قراءة التاريخ (P0):** مرّر لأعلى واقرأ رسائل قديمة وأنت تستقبل
   رسائلًا جديدة — يجب أن يبقى موضعك ثابتًا. أرسل رسالة بنفسك → تنزل
   للأسفل طبيعيًا.
3. **زر الإرسال (P0):** أرسل رسائل متتالية سريعة (بلا رد) — بلا ثقل.
4. **«حالتي الآن» (C-05):** اضبط حالتك ثم أعد تحميل الصفحة وادخل —
   يجب أن تُستعاد الحالة (كانت تُمسح سابقًا بسبب رقعة localStorage).
5. **الرسائل القديمة تظهر «الآن» (C-26):** أرسل رسالة الآن — طابعها
   «الآن» وليس «0د».
6. **قائمة المتصلين:** مرّر بسرعة (تعبئة مختزلة ثم كاملة عند التوقف)،
   النقر على أي عضو يفتح برلفايله (تفويض).
7. **الحائط:** أول فتح بعد الدخول (60 منشورًا) بسلاسة، البقاء في الأعلى
   مع المنشور الجديد كما كان.
8. **الرسائل الخاصة:** محادثة نشطة برسائل متتالية سريعة + عدّاد غير
   المقروء + فتح المحادثة ينزل لآخر رسالة.
9. **كلمة مرور خاطئة (C-26):** رسالة خطأ واحدة فقط (كانت اثنتان).
10. **سجل المطور (Console):** لا أخطاء جديدة.

## خامسًا: ما لم يُغيّر عمدًا

- **C-23:** مسار استرجاع الرسائل الأقدم من سقف ال36 — قرار منتج يتطلب
  API جديد من السيرفر (جاهز للتنفيذ بموافقتك في مرحلة تالية).
- أسماء أحداث Socket.IO وبروتوكولاتها: لم تُمس نهائيًا (u^ الجزئي متوافق
  تنازليًا مع العميل القديم لأن معالجه يستخدم Object.assign أصلًا).
- التصميم والقوالب وترتيب الرسائل وشكل الأزرار: كما هي بالضبط.

## ميزة جديدة (v3): الإرسال اللحظي مع «إعادة إرسال» عند انقطاع النت — رسائل الغرفة

الملفات: `public/x2.js` (دوال `__opt*` قبل Tsend + سطر في `case "msg"`) ، `server.js` (فرع SEND_EVENT_EMIT_MSG)،
`public/index.ejs` (ترقية x2.js إلى ?87). العلامة في الكود: **[FIX-OPT]**.

**السلوك:**
1. عند الضغط على إرسال: الرسالة تظهر عند المرسل فورًا بشكلها العادي تمامًا (بلا ضبابية) — قبل أي رد من السيرفر.
2. عند وصول بث السيرفر (يُطابَق بمعرّف `cid`) تُستبدل الفقاعة المؤقتة بنسخة السيرفر النهائية
   (بعد فلتر الاختصارات/الطول/الروابط) — بنفس الشكل والترتيب كما كان.
3. لو السيرفر رفضها (إسكات / عدد لايكات غير كافٍ / فلتر كلمات / فارغة): تُحذف الفقاعة
   وإشعار السيرفر يظهر كالمعتاد.
4. لو النت مقطوع وقت الإرسال، أو لم يصل رد خلال 8 ثوانٍ: تتحول الفقاعة إلى «لم تُرسل» مع
   **إعادة إرسال** و**حذف**. (لا نُطلق الإرسال والاتصال مقطوع حتى لا يخزّنه socket.io ويكرره لاحقًا.)
5. إعادة الإرسال تستخدم نفس `cid`، والسيرفر يحتفظ بالمعرّفات 120 ثانية: لو الرسالة كانت وصلت
   فعلًا وضاع الرد فقط، لا يبثها ثانية — يعيد الرد للمرسل وحده (لا تكرار في الغرفة).
6. أي فشل في الرسم اللحظي يرجع للإرسال القديم نفسه (الرسالة لا تضيع أبدًا).

**التوافق:** أسماء أحداث Socket.IO نفسها؛ `cid` حقل اختياري + ack اختياري، فالعميل القديم
(بدون الملف الجديد) يعمل مع السيرفر الجديد والعكس. **التركيب: أعد تشغيل السيرفر.**

**خارج النطاق عمدًا:** الرسائل الخاصة (sendpm) والصور/الفيديو/الصوت (مسار رفع مستقل) — لم تُغيَّر.

**اختبارات أجريتها:** محاكاة آلية لمنطق العميل (17 حالة) والسيرفر (12 حالة): نجاح، رفض، انقطاع، إعادة إرسال
بنفس cid، تكرار، غياب الـack، عميل قديم، فشل الرسم. لم تُجرَّب على متصفح/سيرفر حيّ.

**فحص حي بعد النشر:** (1) أرسل رسالة: تظهر لحظيًا ثم تثبت. (2) أطفئ الواي فاي ثم أرسل: تظهر «لم تُرسل».
(3) شغّله وانقر «إعادة إرسال»: تصل مرة واحدة فقط. (4) جرّب بحساب مُسكَت: لا تبقى فقاعة عالقة.
